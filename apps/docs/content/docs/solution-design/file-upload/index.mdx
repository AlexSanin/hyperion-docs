# File Upload with Document Processing

We aim to build a secure, scalable file upload system that accepts user-submitted documents, scans for malware, and processes them through our document intelligence pipeline with real-time status tracking.

## Scope

### In Scope

- [x] Single file upload via REST API
- [x] Bulk upload (multiple files in one request)
- [x] Presigned URL support for direct-to-S3 upload
- [x] Virus scanning with ClamAV
- [x] Format validation (PDF, DOCX, XLSX, PPTX, TXT, HTML, images)
- [x] Size limits (100MB per file, 1GB per bulk upload)
- [x] Tenant-isolated S3 buckets
- [x] Processing pipeline integration (OCR, NER, Classification)
- [x] Job status polling endpoint
- [x] Deduplication (exact and near-duplicate detection)

### Out of Scope

- [ ] Drag-and-drop UI (frontend concern)
- [ ] Folder upload with structure preservation
- [ ] Mobile-specific upload handling
- [ ] Offline sync / resume interrupted uploads
- [ ] Real-time processing progress (WebSocket)

## Research

**1. Virus Scanning Integration** — ClamAV provides open-source virus detection with daily signature updates. For enterprise scale, we can swap to commercial solutions (Sophos, CrowdStrike) via abstraction layer. Scanning adds ~500ms per file.

**2. Direct-to-S3 Upload** — For large files (>10MB), presigned URLs allow clients to upload directly to S3, bypassing our API servers. This reduces load and enables resumable uploads. Trade-off: client needs S3 SDK or multipart upload handling.

**3. Deduplication Timing** — Dedup can run pre-processing (reject early) or post-processing (after OCR has extracted text). Decision: Run hash-based dedup before processing, SimHash after text extraction for near-duplicate detection.

**4. Bulk Upload Limits** — Testing showed 50 concurrent uploads per tenant is sustainable. Beyond that, queue depth grows faster than workers can process. Implement per-tenant rate limiting with configurable thresholds.

**5. Format Detection** — Don't trust file extensions. Use libmagic / file signatures to detect actual format. Mismatch between extension and content triggers warning but doesn't block upload.

## Risks & Solutions

### Technical Risks

| Risk                         | Impact                       | Mitigation                                                       |
| ---------------------------- | ---------------------------- | ---------------------------------------------------------------- |
| Virus scanner false positive | Medium — valid file rejected | Manual override with audit trail, admin approval flow            |
| S3 upload timeout            | Medium — upload fails        | Presigned URLs with multipart, client-side retry                 |
| Processing queue saturation  | High — backlog grows         | Auto-scaling workers, per-tenant quotas, alerting on queue depth |
| OCR accuracy on poor scans   | Medium — garbled text        | Quality threshold, flag for manual review if confidence < 70%    |

### Stability Concerns

- [ ] ClamAV daemon must be running; implement health checks and fallback
- [ ] S3 outage blocks all uploads; no local fallback (by design for compliance)
- [ ] Large bulk uploads can starve other tenants; implement fair queuing

### User Communication

- [ ] Supported formats documentation
- [ ] Size limits and error messages
- [ ] Processing status UI component
- [ ] Retry guidance for failed uploads
